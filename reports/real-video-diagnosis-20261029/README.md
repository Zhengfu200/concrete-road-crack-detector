# 实际路面视频整幅大框问题诊断

日期：2026年10月29日。仅进行复现和诊断，没有修改模型、阈值、视频或默认入口。

## 已确认现象

07入口加载检测头微调第2轮候选，权重SHA-256为46a50d74d5238981a183a1bb87ae2a2eb04bce9eead10150c7b379e61843f913，默认置信度阈值0.03675317019224167，NMS0.3。入口没有误加载其他模型。

均匀抽取24帧，24帧都有预测；15帧存在覆盖本帧80%以上的框，13帧覆盖90%以上；13帧存在覆盖80%以上且置信度≥0.5的框。这不是全片误检率，也没有人工真值，不能计算真实Precision/Recall。

例如视频14.13秒时，原模型输入画布992×992，网络直接输出xyxy约[30.61,23.13,969.05,958.00]、分数0.6987。还原到原406×406图像后的归一化框约[0.0152,0.0074,0.9928,0.9813]，面积95.20%。大框在GUI绘制之前已存在，不能解释为窗口拉伸或显示代码把小框放大。

## 原视频与裁剪版对照

同一24个帧序号，保持相同推理协议；下表统计“存在占各自画面面积≥80%、分数≥0.5的框”的帧数。

| 模型 | 原406×720竖屏 | 406×406裁剪版 |
| --- | ---: | ---: |
| 原100轮模型 | 2/24 | 9/24 |
| 当前检测头微调模型 | 5/24 | 13/24 |
| 背景补充候选 | 0/24 | 1/24 |

裁剪版本改变视野、宽高比、像素缩放尺度，并经过重编码；本对照未单独分离这些因素。由于两版视野和面积分母不同，上述统计不能当作严格的误检率因果估计。但它明确说明，之前裁剪并没有解决当前模型的大框现象；仅验证可解码和可推理不足以证明它适合检测效果。

背景候选抑制了这种高分大框，但可能同时抑制真正裂缝。当前不依据未标注视频上的框数擅自替换模型。

## 训练数据核对

当前检测头模型的V2训练集3073张，全部有裂缝标签，无正常表面负样本。共有3167个GT框：373个面积≥50%，60个≥80%，26个≥90%，框面积中位数20.72%。整体裂缝的轴对齐框可以包含较多正常路面，但不能说大多数训练框都标成整幅画面，也不能据此宣布冻结标注规则错误。

背景补充版本增加62个训练裁剪，但当前默认预览使用的检测头候选没有在这些裁剪上训练。它们也不能替代完整画幅、实际拍摄条件下的正常路面、阴影、接缝与纹理负样本。

## 解释与边界

已确认的是网络输出高分大框、背景训练覆盖不足及实际拍摄条件下表现不可靠。最符合现有证据的解释是模型对实际路面背景的抑制和场景泛化不足，可能依赖纹理或整体外观等不可靠线索；具体依赖什么特征尚未用因果实验确认。运动模糊、接缝与训练/实际场景差异均应纳入复核。

默认阈值约0.037会保留更多低分框，但不能解释为何0.7至0.8分的大框也出现。提高阈值只能筛选已有预测，不能纠正高置信度的错误定位；按面积删除大框也不能当作模型精度改善，可能删掉真正跨画面的连通裂缝。

界面显示的crack分数来自模型confidence字段，不是经真实道路数据校准后的正确概率，也不是准确率。置信度越高不代表不会误检。接口字段说明见[Ultralytics预测结果文档](https://docs.ultralytics.com/modes/predict/)。

之前的90帧检查仅证明输入兼容、运行无错误；此前已注明不是准确率验证，但没有充分检查实际大框误检，不足以证明裁剪版改善检测效果。

## 后续处理方向

优先在真实视频中建立带人工复核的开发样本，覆盖完整正常画面、接缝、阴影、粗糙纹理、运动模糊及真实裂缝，比较三个模型的误检与漏检。该视频早已用于开发演示和本次诊断，不当作全新的独立验收集。训练/开发/验收应按拍摄批次或路段隔离，相邻视频帧不能随机拆分后声称独立泛化。

在真实场景对照前，不自动调整置信度阈值、按面积隐藏大框、将预测框保存为真值、宣布已通过验收或重新训练模型。

证据：`diagnosis.json`保存24帧的原始画布框和还原框及训练集统计；`model-video-comparison.json`保存三模型两种视频的逐帧对照；`reproduced.jpg`为12个时刻的预测图册。
